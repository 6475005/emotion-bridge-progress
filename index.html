01 / MODEL ARCHITECTURE

二つのモデル、
一つの逐次処理パイプライン。

二つのモデルを音声でつなぐカスケード方式です。音声エンコーダーはQwenの既存部品を再利用しますが、身体拡散モデルは別のパラメータと学習損失を持ちます。

「統合」の実装

Qwenと身体モデルを同じ常駐ワーカーに保持し、応答ごとのIDと音声ハッシュで接続。既存の音声エンコーダーを再利用してGPU上の重複ロードを避けます。一つのリクエスト内で逐次実行し、生成終了後に音声・動作を同期再生します。

身体モデル内部

幅256・12ブロックの共有系統を基礎に、骨格別の入力・出力投影と動作コーデックを持ちます。採用v5の身体学習対象は14,055,926パラメータ。これはQwenを含む総パラメータ数ではありません。

区別現在の構成
対話の履歴前の発話と実際のQwen返答を次ターンへ渡す
動作の履歴同一返答内で前窓の生成末尾30フレームを使う。返答をまたぐ履歴はリセット
動作への意味入力採用ライブ経路は応答音声の特徴が条件。返答テキストを身体モデルへ直接渡す経路は採用していない
英語と日本語共有モデルの別出力経路。骨格差を同一関節数の埋め草で隠さない
時間的な生成完成音声 → 特徴抽出 → 身体生成 → 同期再生。音声生成中の身体ストリーミングは未実装
学習方法と正規化の要点

日本語・ZEGGSは潜在動作、Trinityは姿勢と動的成分を予測します。凍結したデコーダーを通した動作損失と、拡散の予測損失を併用。生成履歴は条件付けに使い、正解動作を生成物へ置き換えていません。統計は学習分割から計算し、Qwen・既存英語経路・各コーデックを凍結して継続しました。

Trinity追加の8k→16k継続：日本語batch32、ZEGGS16、Trinity16、相対損失重み1 : 0.25 : 0.25。既存AdamWの状態を復元し、新規Trinityテンソル10個だけを新しいoptimizer状態から開始。生成履歴混合率0.5、音声・履歴dropout0.1。これらは過去に実行した採用系統の仕様で、現在新規学習を行っているわけではありません。

01B / MOTION LEARNING & REVIEW

人間動作から学ぶ。
比較して、採否を決める。

学習時の入力は、収録された音声と対応する人間動作。運用時には、実際のQwen返答音声を同じ特徴経路へ通します。ここでは採用モデルの学習系統と、その後に検証した未採用候補を区別します。

  1. 01

    対応する音声と人間動作を整理

    元記録ID・時計・骨格・除外理由を保持。記録単位で学習／開発を分割し、4秒窓へ。

  2. 02

    凍結した特徴と動作表現

    Qwen音声特徴52×2048。ソース別コーデックで動作を符号化し、学習分割の統計で正規化。

  3. 03

    音声条件付き身体拡散モデルを学習

    教師動作のコードにノイズを加え、音声・履歴・拡散時刻からvを予測。共有ブロックと骨格別投影を更新。Qwenとコーデックは凍結。

  4. 04

    完全な状態から対照継続学習

    16kの全重み・AdamW・乱数状態を復元。同じデータ・ノイズ列で対照と介入を比較。生成履歴は条件であり、観測教師の代用品ではない。

  5. 05

    数値と再生で採否を決める

    位置・時間変化・境界・多様性と実際の返答を確認。訓練損失の低下や滑らかさだけでは採用しない。現在は元のv5をライブ接続。

一つの学習バッチで何を最適化するか

teacher motion → frozen codec → normalized clean code z
x_t = a(t) · z + b(t) · noise
v_target = a(t) · noise − b(t) · z
v_pred = body(x_t, audio_features, history, t)
clean_estimate = a(t) · x_t − b(t) · v_pred
decoded_motion = frozen_decoder(denormalize(clean_estimate))
