HUMAN–ROBOT INTERACTION · 2026.09.14

会話に、
学習した身体表現を。

人間の動作から学んだ振る舞いは、小型ロボットとの対話に親近感や共感を生むか。

日本語・英語Qwen3-Omni + learned bodySota実験準備
確認済み：逐次生成と同期再生。未実施：実機・参加者評価。
Qwenが応答音声を生成した後、その音声から身体動作を生成します。音声・身体の同時生成や一体学習を達成したという意味ではありません。

01 / INPUT → OUTPUT

どんな会話を、
どう返すのか。

入力の例

「今日は発表で失敗して、少し落ち込んでいます。」
現在検証した経路：テキスト＋実際の会話履歴＋明示した言語。音声・画像入力は基盤モデルの機能ですが、最新の身体統合経路では未検証です。

出力の例

返答文＋Qwen自身の音声＋30 Hzの身体動作列。現在はブラウザーの模式図で同期再生します。実機では関節への写像と制御器への送信を追加します。
図のうなずき・腕の動きは想定例で、意味に合う動作を保証するものではありません。

想定する場面は、発表後の落ち込み、課題を終えた喜び、翌日の予定などの短い日常会話です。医療・カウンセリング効果は研究主張に含めません。

「統合」の実装

Qwenと身体モデルを同じ常駐ワーカーに保持し、応答ごとのIDと音声ハッシュで接続。既存の音声エンコーダーを再利用してGPU上の重複ロードを避けます。一つのリクエスト内で逐次実行し、生成終了後に音声・動作を同期再生します。

身体モデル内部

幅256・12ブロックの共有系統を基礎に、骨格別の入力・出力投影と動作コーデックを持ちます。採用v5の身体学習対象は14,055,926パラメータ。これはQwenを含む総パラメータ数ではありません。

区別現在の構成
対話の履歴前の発話と実際のQwen返答を次ターンへ渡す
動作の履歴同一返答内で前窓の生成末尾30フレームを使う。返答をまたぐ履歴はリセット
動作への意味入力採用ライブ経路は応答音声の特徴が条件。返答テキストを身体モデルへ直接渡す経路は採用していない
英語と日本語共有モデルの別出力経路。骨格差を同一関節数の埋め草で隠さない
時間的な生成完成音声 → 特徴抽出 → 身体生成 → 同期再生。音声生成中の身体ストリーミングは未実装
学習方法と正規化の要点

日本語・ZEGGSは潜在動作、Trinityは姿勢と動的成分を予測します。凍結したデコーダーを通した動作損失と、拡散の予測損失を併用。生成履歴は条件付けに使い、正解動作を生成物へ置き換えていません。統計は学習分割から計算し、Qwen・既存英語経路・各コーデックを凍結して継続しました。

Trinity追加の8k→16k継続：日本語batch32、ZEGGS16、Trinity16、相対損失重み1 : 0.25 : 0.25。既存AdamWの状態を復元し、新規Trinityテンソル10個だけを新しいoptimizer状態から開始。生成履歴混合率0.5、音声・履歴dropout0.1。これらは過去に実行した採用系統の仕様で、現在新規学習を行っているわけではありません。

03 / PROTOTYPES & DECISIONS

何を試し、
何を残したのか。

09.09

対話・音声・模式動作の接続試作

まずUIとQwenの接続を成立させた。初期の人手設計の動作教師は統合確認用で、人間動作学習の成果ではない。

09.11

実データと身体拡散モデル

BEAT2の日英比較、GENEA対話データの別系列試作。小型モデルから容量拡大と時間損失を検討したが、速度・方向・言語間のトレードオフが残った。

09.12

日本語の骨格をそのまま学習

日本語アーカイブを120Dの独立経路へ変換。欠けた脊椎関節を捏造せず、コーデックと生成履歴を導入。

09.13

ZEGGS・Trinityの共有化

スタイル付きZEGGS、姿勢を明示的に扱うTrinity経路を追加。完全なモデル・optimizer状態を保持して16kまで継続。

09.13–14

改善しない候補も残して不採用

回転合成・デノイズ損失・履歴・内容条件付けを比較。数値の一部が良くても、継ぎ目・動きの分布・返答への適切さを満たさない候補は採用しなかった。

09.14

実応答の常駐生成とブラウザー接続

元のfull-v5を使い、実応答音声→身体生成→同期再生を接続。人間並みの再現より、短時間Sota実験の成立を優先。

狙う貢献は、音声・動作生成の世界初や、最速・最高のリアリティという主張ではありません。人間動作の学習を日本語・英語の対話基盤に接続し、Sotaで表現できる振る舞いと人の受け止め方を評価することです。
